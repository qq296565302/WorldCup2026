# Git 提交信息规范

## 语言

- 提交信息必须使用**中文**撰写
- 不要中英文混用（专有名词除外，如 Vue、Vite、API）

## 格式

采用 **约定式提交（Conventional Commits）** 格式：

```
<类型>(<作用域>): <简短描述>

<可选的详细说明>
```

- 标题行不超过 **50 个字符**
- 标题行结尾不加句号
- 空一行后写详细说明（如有必要）
- 详细说明每行不超过 **72 个字符**

## 类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(球员): 新增球员详情页雷达图` |
| `fix` | 修复缺陷 | `fix(赛程): 修复比赛时间显示为 UTC 的问题` |
| `style` | 样式/UI 调整（不影响逻辑） | `style(首页): 调整赛程卡片圆角和阴影` |
| `refactor` | 重构（既不修复缺陷也不添加功能） | `refactor(服务层): 统一 API 错误处理逻辑` |
| `perf` | 性能优化 | `perf(球员数据): 按球队拆分球员数据实现按需加载` |
| `docs` | 文档变更 | `docs: 更新 README 运行说明` |
| `chore` | 构建/工具/依赖变更 | `chore: 升级 Vue 至 3.5 版本` |
| `test` | 测试相关 | `test(工具函数): 补充日期格式化单元测试` |
| `ci` | CI/CD 配置变更 | `ci: 添加 GitHub Actions 自动部署` |
| `revert` | 回退提交 | `revert: 回退球员数据拆分方案` |

## 作用域

作用域用于标识变更涉及的模块或页面，使用以下标准作用域：

| 作用域 | 对应内容 |
|--------|----------|
| `赛程` | 首页赛程列表、比赛卡片 |
| `球队` | 球队列表、球队详情页 |
| `球员` | 球员详情页、球员数据 |
| `积分` | 小组积分榜 |
| `比赛` | 比赛详情页 |
| `路由` | Vue Router 相关 |
| `服务层` | API 调用、HTTP 客户端 |
| `数据` | 静态数据文件（teams.js、squads.js 等） |
| `样式` | 全局样式、设计系统 |
| `组件` | 通用组件（MatchCard、PageHeader 等） |
| `工具` | 工具函数、数据采集脚本 |

- 作用域为**可选项**，当变更涉及多个模块时可省略
- 作用域用中文，不用英文

## 规则

1. **一个提交只做一件事** - 不要把功能开发和样式调整混在同一个提交
2. **标题用祈使句** - 用"新增"而不是"新增了"，用"修复"而不是"修复了"
3. **详细说明写"为什么"** - 标题写做了什么，正文写为什么这么做（如果原因不明显）
4. **关联 Issue** - 如有相关 Issue，在正文末尾添加：`Closes #123`
5. **不提交临时文件** - 不要提交 `team.html`、`dq_match_sample.html` 等临时爬取文件

## 示例

```
feat(球员): 新增球员能力雷达图

使用 SVG 绘制六维雷达图，展示速度、力量、防守、
盘带、传球、射门六项能力值，支持动画过渡效果。

Closes #42
```

```
fix(赛程): 修复已结束比赛仍显示"未开始"

原因是状态判断逻辑未覆盖加时赛和点球大战的情况，
统一使用 matchStatus 字段进行判断。

Closes #58
```

```
perf(球员数据): 按球队拆分球员数据文件

原 players.js 单文件 56000+ 行导致首屏加载缓慢，
按球队拆分为独立模块并通过动态 import 按需加载，
首屏 JS 体积减少约 80%。
```

```
chore: 初始化 ESLint + Prettier 配置
```

```
style(首页): 优化赛程卡片在深色模式下的对比度
```
